## Sending Messages — Confirmed Working Method

The bridge at `localhost:3000` requires a **Bearer token** for auth. Fetch it from the running process environment before any send.

**⚠️ Group ID correction (confirmed Jun 2 2026):** The Tahmeed group is `120363426592331480@g.us` (*Tahmeed's Growth*). The ID `120363425196031209@g.us` returns `{"error":"item-not-found"}`. Always use the confirmed ID.

```python
import subprocess, json

# Bridge runs as child of hermes-agent (PID 2009 as of Jun 2026 — PID may change after restart)
# Find it dynamically rather than hardcoding:
result = subprocess.run(['pgrep', '-f', 'bridge.js'], capture_output=True, text=True)
bridge_pid = result.stdout.strip().split('\n')[0] if result.stdout.strip() else '2009'
result = subprocess.run(['cat', f'/proc/{bridge_pid}/environ'], capture_output=True)
env_vars = dict(item.split('=', 1) for item in result.stdout.decode('latin-1').split('\0') if '=' in item)
bridge_token = env_vars.get('WHATSAPP_BRIDGE_TOKEN', '')
```

Then use `execute_code` (not terminal) to send — clean quoting, no shell escaping hell:

```python
with open('/tmp/msg.json', 'w') as f:
    json.dump({"chatId": "120363425196031209@g.us", "message": "Your message"}, f)

result = subprocess.run(
    ['curl', '-s', '-X', 'POST', 'http://localhost:3000/send',
     '-H', 'Content-Type: application/json',
     '-H', f'Authorization: Bearer {bridge_token}',
     '-d', '@/tmp/msg.json'],
    capture_output=True, text=True
)
print(result.stdout)  # {"success":true,"messageId":"..."} = sent
```

**Why execute_code + temp file:** Inline shell quoting of emoji/apostrophes/JSON in `terminal()` is fragile. `execute_code` + `json.dump` to a temp file is reliable every time.

**Without the Bearer token:** Returns `{"error":"Unauthorized"}`. Don't skip the token fetch step.

**PID note:** The bridge runs as a child of hermes-agent (`bridge.js`). PID 349600 was valid early on but is NOT stable — use `pgrep -f bridge.js` to find the current PID. Fallback: read from `/home/hermes/.hermes/.env`:
```python
# Fallback: parse .env directly
for line in open('/home/hermes/.hermes/.env'):
    if line.startswith('WHATSAPP_BRIDGE_TOKEN='):
        bridge_token = line.split('=',1)[1].strip()
```
The `.env` fallback is reliable and simpler than hardcoding a PID. Use it as the primary method if you don't need to read from a live process env.

**Confirmed working:** `{"success":true,"messageId":"...","messageIds":["..."]}` = delivered.

**Do NOT attempt:**
- `hermes messages list` — not a valid hermes subcommand
- `sqlite3 state.db` — not installed on this VM
- Curl with inline `-d '{"message": "..."}` for messages with emoji/apostrophes — use temp file

**Official documents / .gov data / syllabus PDFs (browser hung Jun 2026):** When the
browser tool times out (it did for both the Visa Bulletin and the Cambridge syllabus
pages this session), raw `curl` + `pdftotext` is faster and reliable. Pattern:
```bash
# 1. Find the current resource (e.g. latest Visa Bulletin month, current syllabus PDF)
curl -sL --max-time 30 -A "Mozilla/5.0" "<index-url>" | grep -ioE "<pattern>" | sort -u
# 2. Pull the doc; for PDFs, convert
curl -sL --max-time 40 -A "Mozilla/5.0" "<pdf-url>" -o /tmp/doc.pdf
pdftotext -layout /tmp/doc.pdf /tmp/doc.txt   # then grep the .txt for the Contents/section you need
```
- Always pass `-A "Mozilla/5.0"` — some .gov/edu sites 404 a bare curl.
- **Visa Bulletin:** https://travel.state.gov/.../visa-bulletin.html lists every month;
  grep `visa-bulletin-for-<month>-<year>` to find the latest, then pull that month's page
  and grep the `F2A` row (Final Action Dates + Dates for Filing).
- **Cambridge syllabus:** the subject page (e.g. O Level English Language = code **1123**)
  links the syllabus PDFs under `/Images/<id>-<years>-syllabus.pdf`. Match the PDF to the
  EXAM SITTING year — Oct 2026 = the 2024–2026 syllabus; 2027+ sittings use the 2027–2028
  syllabus (the spec changes between them, so confirm the sitting date first).

**Past papers — finding actual question papers (browser hung Jun 2026):** Most mirror
sites are dead ends — `gceguide.com`/`papers.gceguide.com` redirect to ad pages, `papersdaddy`,
`papersbay`, `bestexamhelp`, `xtremepape.rs`, `theallpapers` all 404'd or 503'd this session.
The ONE live, scriptable source was **`pastpapers.papacambridge.com`**:
```bash
# 1. Index page for a subject+series lists every PDF as download_file.php?files=<direct-url>
curl -sL --max-time 25 -A "Mozilla/5.0" \
  "https://pastpapers.papacambridge.com/papers/caie/o-level-english-language-1123-2024-oct-nov" \
  | grep -oiE 'href="[^"]*1123_w24[^"]*"' | sort -u
# 2. The files= param is the DIRECT pdf URL — pull it straight:
curl -sL --max-time 40 -A "Mozilla/5.0" \
  "https://pastpapers.papacambridge.com/directories/CAIE/CAIE-pastpapers/upload/1123_w24_qp_11.pdf" \
  -o /tmp/qp.pdf
pdftotext -layout /tmp/qp.pdf -   # read the actual questions
```
- Paper code convention: `<syllabus>_<season><yy>_<type>_<variant>.pdf` — season `s`=May/June,
  `w`=Oct/Nov; type `qp`=question paper, `ms`=mark scheme, `in`=insert, `gt`=grade thresholds;
  variant `11/12/21/22` etc. So `1123_w24_qp_21` = English, Oct/Nov 2024, Paper 2 var 1.
- **When you can't guess the live URL, scrape DuckDuckGo HTML** (`html.duckduckgo.com/html/?q=...`)
  and decode the `uddg=` params — that's how the working papacambridge path surfaced after
  every other mirror failed. Verify the download is a real PDF (`file /tmp/x.pdf` → "PDF document"),
  not an HTML 404/error page masquerading with a .pdf URL.
- **Always read the PDF before reporting** — don't hand over a link blind; convert and confirm
  it's the genuine paper. (Oct/Nov 2024 1123: Paper 1 Reading = "The World's Oldest Swim" +
  "Volunteering to work with animals" summary; Paper 2 Writing = social-media directed article +

## Delivering Task Batches — Video Link Verification

Before sending any batch of YouTube tasks to Tahmeed, verify every link:

```bash
yt-dlp --get-title --get-duration --no-warnings "URL" 2>&1
```

- `yt-dlp --get-title` will return `ERROR: Video unavailable` for dead links.
- Install if missing: `pip install yt-dlp --break-system-packages`

**Replacement search pattern:**
```bash
yt-dlp "ytsearch3:<topic keywords>" --get-id --get-title --get-duration --no-warnings
```
Then spot-check the top result with `--get-description` to confirm it covers the described content.

**Fallback when browser tools timeout (Jun 2026):** YouTube search via browser_navigate can hang. Raw curl + grep is faster and reliable:
```bash
# Search and extract video IDs
curl -s "https://www.youtube.com/results?search_query=topic+keywords" | grep -oP 'watch\?v=[^"&]+' | head -5

# Get video title to verify it's the right one
curl -s "https://www.youtube.com/watch?v=VIDEO_ID" | grep -oP '<title>[^<]+' | head -1
```
This avoids browser timeout issues entirely and works when yt-dlp isn't installed.

**Reestablish = full re-verify + replace dead links before resending.** Never just update attribution — check all links in the batch.
