# Serial Question Pattern (User Preference)

**Established:** June 8, 2026 during TIMBR advisory LOI task (Maureen proposal)

**Context:** User was 20 minutes from Fluxx Labs interview. Needed quick answers on cap table structure. I fired multi-question blocks:
- "What equity percentage are you offering? What's the vesting schedule? What's the timeline? What's the structure?"

User corrected with voice message: **"Ask me only one question at a time."**

## The Pattern

When you need sequential input across multiple decision dimensions:

**WRONG:**
```
What equity percentage are you offering Maureen?

Also: What vesting schedule? Cash component or equity-only? 
Timeline? Anything else I should know?
```

**RIGHT:**
```
What equity percentage are you offering Maureen?
```

[Wait for response. User provides answer. Then ask the next question.]

```
What vesting schedule?
```

[Wait. Then next question.]

## Why This Matters

1. **Cognitive load under time pressure:** Multi-question prompts force context-switching. When user is busy or has time pressure (interviews, meetings, deadlines), serial questions reduce friction.

2. **Natural pacing:** Serial questions let the user drive the tempo. They answer, you synthesize, you ask the next clarifying question based on what they said. This is how humans naturally converse.

3. **One decision per turn:** Each question gets focused attention. User doesn't have to hold multiple decision threads.

## Application Areas

- Cap table decisions (equity %, vesting, anti-dilution, timeline)
- Requirements gathering (when building a doc or system)
- Troubleshooting (one diagnostic at a time)
- Configuration (one setting per turn, unless user asks for a menu)

## Exception

If user explicitly asks for options ("What are my choices?") or a menu ("Show me alternatives"), then batch is okay. But default is serial.
