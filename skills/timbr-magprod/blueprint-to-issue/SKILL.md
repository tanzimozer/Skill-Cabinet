# Blueprint → issue content

Use when fleshing out a started issue's sections.

Steps:
1. Read the blueprint structure (sections, tone, length per section).
2. For each section, draft to the blueprint's spec; keep the house voice consistent across the issue.
3. Flag sections that need a trainer asset or Tanzim input rather than guessing.
4. Track section status in the issue checklist (draft / review / final).

Pitfalls: don't deviate from blueprint structure without flagging; don't fabricate trainer-specific content — request it.
Verify: every blueprint section has a status; no invented trainer data.
